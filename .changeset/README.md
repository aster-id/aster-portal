# Changesets

## Aster release batching

Merge code independently of releases. Keep `package.json` at Aster's last released version when integrating upstream; do not adopt Eurosky's version bumps or finalized release entries as Aster releases.

Record pending Aster release notes in changeset files, using the package name `eurosky-portal` and the appropriate bump (for example, `patch`). Preserve upstream attribution in those notes. Additional merges may add changesets or extend the existing pending notes.

Pushing these changes to `main` builds the `dev` image and lets Changesets create or update the **Prepare next release** PR. Leave that PR open while collecting changes. Review its version and changelog, then merge it only when ready to release: the release workflow tags the new version and publishes the versioned image and `latest`, which production watches for updates. Arrange the database backup before releasing migrations.

Do not run `pnpm version-package` on `main` while still collecting changes; that finalizes the version bump and consumes the pending changesets. A manual version bump without pending changesets can also trigger publication on the next push.
